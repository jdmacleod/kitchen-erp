# Phase 4 acceptance audit

Each criterion of sub-phase 4A from `docs/spec/17-phase-4-lists-and-trips.md`
(1–10) and each UI criterion it builds from `docs/spec/11-ui-acceptance-criteria.md`
(the returned UI-2.4 to UI-2.7, and UI-8.1 to UI-8.11, 8.19 and 8.20), with the
test or procedure that demonstrates it. Backend tests live under
`backend/tests/`, frontend unit tests under `frontend/src/test/`, browser tests
under `e2e/tests/`. The browser tests make their own kitchens, ingredients and a
member through the API on the throwaway e2e stack, and add the example recipe
`basics/self-raising-flour.cook` (MIT) to a list (two of its three lines land;
salt is on the negligible list, 07 criterion 16); the backend tests use the
invented dishes inlined in `test_shopping_lists.py`. 4B and 4C are not yet
built; their criteria (11–22 of `17`, UI-8.12 to 8.18) are not audited here.

## Notes

- The per-kitchen cost view (`recipe_costing.compute_view`) builds an unsaved snapshot and unsaved lines from the same costing step as the stored snapshot (`cost_recipe`), so a kitchen's figures and the household's are costed by one rule; `recipe_cost_views.cost_out` reads either.
- The browser spec signs in as a member it creates per worker, because the current kitchen is a per-user server setting and the projects run in parallel against one backend. A new member has no setting, so the chain resolves one; the switcher test reads which and switches to the other first, so both switches are real and both PUTs are seen.
- Two things the browser tests found and package 4 fixed: the "from recipe" link on a row was 16px tall on a phone (UI-8.11), and after "Start a fresh list" from the More actions sheet, focus went back to the sheet's opener rather than to Cancel (UI-8.2).
- The wording tidies of package 4 (`10`, `11`, `17`: the product switch, the counts after writing, "from recipe", name and pack, unmarked carried items, the stale notice) are each marked "(package 4, 2026-10-12)" in the spec.
